# /bro

Restate your last reply so the user understands it on one read. Same facts and the same conclusion, plainer words. Do not run tools, do new work, or change the conclusion. If the args name a part, restate only that part.

- Open with the conclusion in one sentence.
- Write whole sentences with their subject and verb. No arrows, symbol-speak, or dropped particles: "A → B, 0.2% 다리" becomes a sentence that says what happened to what.
- Replace every label you coined in this chat (option letters, "B-부팅", internal ids, abbreviations) with what it stands for. A term that has to stay gets a one-line explanation the first time.
- Show one concrete case from this work (a real file, node, request, number) instead of a general statement.
- Numbers that are compared go in a small table.
- Drop lessons and evaluative framing ("this shows that ..."). State what happened, what it means for the user, and what they need to decide.
- Plain beats short. Keep a step the user needs even if it makes the reply longer.
