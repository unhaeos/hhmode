# 리포트 작성 표준

사용자가 여러 번 교정한 끝에 확정된 형식이다. 이 형식을 벗어난 장식적 디자인을 만들지 말 것.

## 원칙

**문서는 읽는 것이다.** 리포트는 대시보드가 아니다. 표가 사실을 나르고, 본문은 표가 못 말하는 것만
적는다. 그 외의 시각 장치는 소음이다. arXiv 논문/테크리포트가 기준 이미지.

**분량 규칙** — 한 절에 문단 3개 이하. 표로 적을 수 있으면 표로 적고 문단으로 반복하지 않는다.
설계·구성 같은 절은 문단 대신 표 하나로 끝내는 편이 낫다. 문서 전체 문단 수가 표 개수보다
많으면 설명이 과한 것이다.

## 금지 목록 (AI-slop 패턴)

- stat 카드 그리드 (숫자 크게 + 라벨, 나란히 3개)
- 태그/뱃지/pill (상태를 알약 모양으로)
- step 카드 플로우 (박스 나열로 단계 표현 → 번호 리스트 `<ol>`로 쓸 것)
- eyebrow 라벨 (대문자 자간 벌린 머리말)
- **문서 맨 위 메타 태그 줄** — `2026-09-30 · 로컬 Qwen · 198문항 1회 · eval/kgqa` 같은
  가운뎃점으로 이어 붙인 머리말. 날짜·환경은 colophon 에 적거나 본문 첫 문단에 녹인다.
- **질문형 제목** — 문서 제목과 섹션 제목 모두. "지식그래프가 검색보다 나은가",
  "무엇을 재려 했나", "왜 중요한가". 자문자답 구조라 읽는 사람이 답을 기다리게 만든다.
- **행위 나열 부제** — "여섯 가지를 나란히 재고, 격차를 둘로 나눴다" 처럼 한 일을 열거하는 부제.
  부제는 결론이나 핵심 수치를 말한다.
- 이모지·아이콘 섹션 마커
- 그라데이션, 카드 안에 카드, 좌측 색 바 붙은 callout 남발
- 배경색 박스 남발 — 요약도 박스가 아니라 리드 문단 + 리스트로

## 레이아웃·타이포

- 한 컬럼, `max-width: 720px`, 여백 넉넉히 (`padding: 56px 24px 96px`)
- 폰트: `Noto Sans KR` (Google Fonts, weight 400/600/800) + 숫자·코드용 `JetBrains Mono`
- **화질**: `html { -webkit-font-smoothing: antialiased; text-rendering: optimizeLegibility; }` 필수 — 한글 웹폰트가 자글자글해 보이는 문제의 해결책. 본문 16px 이상, `line-height: 1.75`, `word-break: keep-all`
- 제목 계층: h1 27px/800 → h2 19px/800 (섹션 번호는 `<span>`으로 앞에, 색은 mute) → h3 16px/800
- 문서 시작: h1 → 부제 한 줄 → **굵은 수평선**(2.5px). 머리말 메타 줄을 넣지 않는다.
  날짜·모델·표본 크기는 colophon 이나 요약 문단에 사실로 적는다.
- 문서 끝: 굵은 수평선 → colophon (재현 자료·파일 경로, mute 색 작은 글씨)

## 색

- 사실상 흑백: 배경 `#FFFFFF`, 잉크 `#191C20`, mute `#5E6672`, 링크 `#1849A9` 하나
- 강조는 `<strong>`(800)과 `<mark>`(연노랑 `#FFF3C2`) 두 가지만. 상태·판정도 색이 아니라 **텍스트로** ("기각", "완료", "대기")
- 다크모드: 토큰(CSS 변수)으로 3-state 지원 (`:root` 라이트 / `prefers-color-scheme: dark`에 `:root:not([data-theme="light"])` 가드 / `:root[data-theme="dark"]`). body에 배경 명시

## 표 (booktabs 스타일)

- 세로선 없음. 상단 2px 룰 + 헤더 아래 1px 룰 + 마지막 행 아래 2px 룰. 행 사이는 아주 연한 1px
- 헤더는 작고(13.5px) mute 색, 굵기 600
- 캡션은 표 위에 좌측 정렬: `<caption><b>표 N.</b> 설명</caption>`
- 숫자 셀: `font-family: JetBrains Mono; font-variant-numeric: tabular-nums`
- 최고 성적 행/셀은 배경색이 아니라 **굵기(800)**로 표시
- 표마다 `overflow-x: auto` 래퍼
- 통계 각주(CI, p값)는 표 아래 `footnote` 클래스 (13.5px, mute)

## 내용 구성 (순서)

1. 제목 + 부제
2. **요약**: "요약." 으로 시작하는 리드 문단 (핵심 주장 2~3문장, `<mark>`로 핵심 수치 강조) + 대시(—) 리스트로 핵심 결과 2~4개
3. 번호 섹션: 설계 → 결과(표 중심) → 분석/메커니즘 → **검증(스스로 반박한 목록 — 반론/방법/결과 3열 표, 철회한 것도 정직하게)** → 선행 대비 → 한계 → 다음 단계
4. colophon: 재현 파일 경로, 날짜·환경

### 제목 쓰는 법

**문서 제목은 다룬 대상을 명사구로 적는다.** 물음표를 쓰지 않는다.

| 쓰지 말 것 | 쓸 것 |
|---|---|
| 지식그래프가 검색보다 나은가 | 지식그래프 조회와 산문 검색 6조건 비교 |
| 왜 파이프라인이 느린가 | 적재 파이프라인 병목 분석 |

**부제는 결론이나 핵심 수치를 말한다.** 한 일을 나열하지 않는다.

| 쓰지 말 것 | 쓸 것 |
|---|---|
| 여섯 가지를 나란히 재고, 격차를 둘로 나눴다 | 격차의 절반은 턴 수에서 나온다. 구조가 더하는 몫은 +0.129다 |

**섹션 제목도 명사구로 단언한다.** 무엇을 다루는 절인지 제목만 읽고 알 수 있어야 한다.

| 쓰지 말 것 | 쓸 것 |
|---|---|
| 무엇을 재려 했나 | 조건 설계 |
| 왜 이렇게 했나 | 공정성 통제 |
| 어떻게 해결했나 | 수정 내역 |
| 무엇을 알게 됐나 | 효과 분해 |
| 앞으로 무엇을 할까 | 다음 단계 |

결과를 섹션 제목에 넣어도 된다 — "지식그래프가 지는 칸", "예상과 달랐던 것" 처럼
그 절의 결론을 제목이 미리 말하는 편이 낫다.

## 문장

- 결론 먼저, 근거 다음. 수치는 본문에 녹이되 비교의 근거는 표로
- **해석을 문장으로 만들지 않는다.** "격차의 절반은 턴 수에서 나온다" 대신 "0.415 → 0.562" 처럼
  수치를 그대로 적는다. 독자가 읽을 해석을 대신 써 주지 않는다.
- **도치·강조 어순을 쓰지 않는다.** "조건은 여섯이다" → "여섯 조건을 비교했다" 또는 표 제목으로.
- 부정 결과·철회·한계를 숨기지 않는다 — 별도 섹션으로 명시
- 전문용어 첫 등장 시 한 줄 설명 (예: "slip(실행 실수)")

## 문장 검수 (필수) — 글쓰자 파이프라인

리포트 본문은 HTML로 감싸기 전에 `geulsseuja` 스킬(`~/.claude/skills/geulsseuja/SKILL.md`)의 3~5단계를 거친다. 형식이 담백해도 문장이 AI체면 소용없다.

1. 본문 문단을 마크다운/플레인 텍스트로 먼저 쓴다 (`/tmp/<이름>_body.md`).
2. `uv run --project ~/projects/geulsseuja geulsseuja lint /tmp/<이름>_body.md` → "AI 티" 섹션이 비고 판정이 "사람 글 범위"가 될 때까지 걸린 문장만 고친다 (최대 3회).
3. 대화 맥락 없는 서브에이전트에게 본문만 주고 블라인드 비평(글쓰자 5단계 프롬프트). "상"이 있으면 고친다.
4. 그 다음에야 HTML로 조립한다. colophon에 린터 점수와 비평 결과를 한 줄 적는다.
